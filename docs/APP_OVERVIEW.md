# Cleanair 앱 설명

Cleanair는 실내 공기질을 확인하고, 필요한 경우 환기 장치나 스마트 플러그를 제어하며, 화재가 의심될 수 있는 이상 패턴까지 확인하는 앱입니다. 숫자를 단순히 나열하는 데서 끝나지 않고, 센서값을 해석하고 사용자가 바로 대응할 수 있는 흐름을 만드는 것을 목표로 했습니다.

앱의 기본 흐름은 다음과 같습니다.

```text
센서 측정 -> 앱/서버 수신 -> 공기질 판단 -> 알림/그래프/방재모드 표시 -> 플러그 제어 또는 상황 전파
```

## 1. 전체 구성

Cleanair는 네 부분이 함께 동작합니다.

| 구성 | 역할 |
| --- | --- |
| AirGradient 센서 | 실내 공기질 데이터를 측정 |
| Flutter 앱 | 센서 등록, 실시간 확인, 알림 설정, 플러그 제어 |
| Firebase | 센서 데이터 저장, 알림, 방재 판단, 플러그 명령 처리 |
| 웹 상황판 | 여러 센서와 플러그를 지도에서 확인하고 원격으로 대응 |

사용자는 앱에서 센서를 등록하고 위치를 저장합니다. 이후 센서가 Firebase로 데이터를 보내면 앱과 웹 상황판이 같은 데이터를 읽어 현재 상태를 보여줍니다.

## 2. 처음 사용하는 흐름

1. 앱을 설치합니다.
2. AirGradient 센서에 제출용 펌웨어를 설치합니다.
3. 앱에서 센서를 PIN 또는 mDNS로 등록합니다.
4. 센서가 설치된 공간과 위치를 저장합니다.
5. 메인 화면에서 실시간 공기질을 확인합니다.
6. 필요한 경우 Tasmota 플러그를 등록합니다.
7. 알림과 방재모드를 켜고 실제 동작을 확인합니다.

이 흐름이 끝나면 앱은 등록된 센서의 최신 데이터를 계속 읽고, 공기질 상태와 알림, 플러그 제어 상태를 함께 보여줍니다.

## 3. 메인 대시보드

메인 대시보드는 현재 공간의 상태를 가장 빠르게 확인하는 화면입니다. 이 화면은 “지금 괜찮은가?”, “어떤 항목이 문제인가?”, “환기나 장치 제어가 필요한가?”를 한 번에 판단하도록 구성했습니다.

### 3.1 표시되는 값

| 항목 | 단위 | 의미 |
| --- | --- | --- |
| 통합 공기질 지수 | index | CO2, PM2.5, TVOC, 열쾌적성을 함께 반영한 대표 지수 |
| PM2.5 | µg/m³ | 초미세먼지 농도 |
| CO2 | ppm | 환기 상태를 판단하는 주요 지표 |
| TVOC | VOC Index | 냄새, 조리, 화학물질 영향이 반영되는 센서 지표 |
| NOx | NOx Index | 연소원, 외기 유입, 조리 영향 확인에 쓰는 보조 지표 |
| 온도 | °C | 열쾌적성과 방재모드 판단에 사용 |
| 습도 | % | 쾌적성, 곰팡이 위험도, 건강모드 판단에 사용 |

NOx는 실내 오염 원인을 설명하는 데 중요하지만, 현재 통합 공기질 지수의 기본 산식에는 넣지 않았습니다. AirGradient의 NOx 값은 절대 농도라기보다 Sensirion SGP41 계열의 상대 index 성격이 강하기 때문에, 대표 지수보다는 경보, 비교, 방재 판단에서 보조적으로 사용하는 편이 더 자연스럽습니다.

### 3.2 통합 공기질 지수

통합 공기질 지수는 여러 항목의 단순 평균이 아닙니다. 평균을 쓰면 한 항목이 크게 나빠졌을 때 문제가 희석됩니다. 예를 들어 CO2가 1600ppm인데 PM2.5가 낮다는 이유로 전체 점수가 낮아지면, 실제 환기가 필요한 상황을 놓칠 수 있습니다. 그래서 Cleanair는 가장 문제가 큰 항목을 먼저 보고, 기준을 넘은 정도를 더해 표시합니다.

먼저 CO2, PM2.5, TVOC를 기준값에 맞춰 같은 스케일로 바꿉니다.

$$
r_{CO2}=\max(0,\frac{CO2-600}{400})
$$

$$
r_{PM2.5}=\max(0,\frac{PM2.5-15}{35})
$$

$$
r_{TVOC}=\max(0,\frac{TVOC-100}{100})
$$

이 값은 “각 항목이 기준에 비해 얼마나 나빠졌는가”를 나타냅니다.

| 값 | 해석 |
| --- | --- |
| 0 | 기준보다 안정적인 상태 |
| 0~1 | 아직 나쁨 기준은 넘지 않았지만 주의해서 볼 구간 |
| 1 이상 | 해당 항목이 나쁨 기준을 넘어선 상태 |

그다음 가장 나쁜 항목의 점수를 `m`으로 둡니다.

$$
m=\max(r_{CO2},r_{PM2.5},r_{TVOC})
$$

`m`이 1보다 작으면 표시 지수는 `m`을 그대로 사용합니다. `m`이 1 이상이면 이미 나쁨 구간에 들어갔다는 뜻이므로, 기준 초과량을 `e`로 따로 계산합니다.

$$
e=\sum \max(0,r_i-1)
$$

표시 지수는 다음처럼 정리됩니다.

$$
IAQI_{base}=
\begin{cases}
0 & (m=0)\\
m & (0<m<1)\\
1+e & (m\geq1)
\end{cases}
$$

이렇게 하면 지수가 1을 초과하는 순간부터 공기질 개선이 필요한 상태로 읽히고, 초과량이 커질수록 단계가 자연스럽게 올라갑니다.

### 3.3 열쾌적성 보정

온도와 습도는 PM2.5나 CO2처럼 직접적인 오염 농도는 아니지만, 사용자가 느끼는 실내 환경에는 큰 영향을 줍니다. 그래서 기본 지수에 열쾌적성 보정을 작게 더합니다.

쾌적 범위는 온도 20~26°C, 습도 30~60%를 기준으로 봅니다. 이 범위를 벗어날수록 보정값이 커집니다.

$$
D_T=\min(1,\left(\frac{\max(0,20-T,T-26)}{4}\right)^2)
$$

$$
D_H=\min(1,\max((\frac{\max(0,30-RH)}{10})^2,(\frac{\max(0,RH-60)}{20})^2))
$$

$$
D_{thermal}=0.7D_T+0.3D_H
$$

$$
P_{thermal}=0.5D_{thermal}
$$

최종 표시 지수는 다음과 같습니다.

$$
IAQI=\min(6,IAQI_{base}+P_{thermal})
$$

열쾌적성은 공기 오염 지표를 뒤집을 정도로 크게 반영하지 않고, 사용자가 느끼는 불쾌감을 보조적으로 더하는 역할을 합니다.

### 3.4 상태 단계

| 표시 단계 | 지수 범위 | 사용자가 해야 할 일 |
| --- | --- | --- |
| 좋음 | 0 | 현재 상태 유지 |
| 보통 | 0 초과, 1 미만 | 환기 상태와 오염원을 가볍게 확인 |
| 조금 나쁨 | 1 이상, 2 미만 | 환기량을 늘리고 원인 확인 |
| 나쁨 | 2 이상, 3 미만 | 짧은 시간 안에 환기 또는 공기청정 강화 |
| 상당히 나쁨 | 3 이상, 4 미만 | 강한 환기와 오염원 차단 필요 |
| 매우 나쁨 | 4 이상 | 즉시 대응 필요 |

메인 대시보드는 이 지수를 원형 게이지와 직선 색상바로 함께 보여줍니다. 숫자는 현재 상태의 강도를 보여주고, 색상바는 사용자가 어느 단계에 있는지 빠르게 읽게 해줍니다.

## 4. 상세 화면

상세 화면은 “지금 값”보다 “어떻게 변하고 있는가”를 보는 화면입니다. 실내 공기질은 순간값만으로 판단하기 어렵습니다. 조리 중인지, 창문을 열었는지, 공기청정기를 켰는지에 따라 같은 값이라도 의미가 달라집니다.

### 4.1 그래프 범위

| 범위 | 용도 |
| --- | --- |
| 10분 | 순간적인 상승, 조리, 먼지 발생 확인 |
| 1시간 | 환기 효과, 공기청정기 작동 후 변화 확인 |
| 6시간 | 생활 패턴에 따른 변화 확인 |
| 24시간 | 하루 동안의 환기 부족, 취침 중 CO2 상승 확인 |
| 주간 | 반복되는 시간대와 생활 습관 확인 |
| 월간 | 장기적인 실내 환경 경향 확인 |

데이터가 하루치밖에 없으면 주간·월간 그래프 전체를 억지로 채우지 않습니다. 측정된 구간만 선으로 표시하고, 아직 측정되지 않은 미래 구간은 빈 공간으로 남기는 것이 정상입니다. 그래야 사용자가 데이터가 실제로 있는 구간과 없는 구간을 구분할 수 있습니다.

### 4.2 구간 선택 통계

그래프에서 특정 구간을 선택하면 해당 구간의 통계가 표시됩니다.

| 값 | 의미 |
| --- | --- |
| Max | 선택 구간의 최댓값 |
| Min | 선택 구간의 최솟값 |
| Avg | 선택 구간의 평균값 |
| Med | 선택 구간의 중앙값 |

평균과 중앙값을 함께 보여주는 이유는 튀는 값 때문입니다. 예를 들어 조리 순간 PM2.5가 매우 높게 튀면 평균은 올라가지만, 중앙값은 평소 수준을 더 안정적으로 보여줍니다.

평균은 다음처럼 계산합니다.

$$
Avg=\frac{1}{n}\sum_{i=1}^{n}x_i
$$

중앙값은 값을 크기순으로 정렬했을 때 가운데에 있는 값입니다.

$$
Med=median(x_1,x_2,\dots,x_n)
$$

### 4.3 CSV 저장

CSV 저장은 앱 화면에 보이는 그래프를 보고서나 발표 자료에 다시 사용할 수 있게 해주는 기능입니다. 저장되는 파일은 Android 기준으로 아래 위치에 만들어집니다.

```text
Download/AirGradient
```

앱은 가능한 범위 안에서 최근 데이터를 가져오고, 데이터가 30일을 모두 채우지 못해도 실제로 존재하는 구간을 저장합니다. CSV에는 시간, 센서값, 통합 지수, 상태 판단에 필요한 값이 포함됩니다.

## 5. 건강 모드

건강 모드는 공기질을 생활 상황에 맞춰 다시 해석합니다. 같은 PM2.5 값이라도 어린이, 고령자, 수면 환경, 집중 환경에서는 의미가 다를 수 있습니다. 그래서 건강 모드는 단순히 “좋음/나쁨”만 보여주지 않고, 어떤 생활 행동이 필요한지 알려주는 방향으로 구성했습니다.

### 5.1 건강 모드 항목

| 항목 | 주로 보는 값 | 판단 의미 |
| --- | --- | --- |
| 호흡기 건강지수 | PM2.5, CO2, TVOC | 호흡기 부담과 환기 필요성 |
| 고령자 건강지수 | PM2.5, CO2, 온도 | 심혈관·호흡기 부담 가능성 |
| 집중환경 판단 | CO2, 온도, 습도 | 집중하기 좋은 환경인지 확인 |
| 쾌적 수면지수 | CO2, TVOC, 온습도 | 취침 중 환기와 쾌적성 확인 |
| 곰팡이 위험도 | 습도, 고습 지속 시간 | 장시간 고습으로 인한 곰팡이 가능성 |
| 정화속도 k | PM2.5 또는 CO2 변화 | 공기청정기나 환기 효과 확인 |
| CADR Index | 정화속도 k 기반 | 공간 내 정화 성능을 간단히 비교 |

### 5.2 정화속도 k

정화속도 k는 오염물질 농도가 얼마나 빨리 줄어드는지 보는 값입니다. 공기청정기를 켜거나 환기팬을 작동했을 때 농도가 빠르게 내려가면 k가 커집니다.

오염 농도가 시간에 따라 지수적으로 감소한다고 보면 다음처럼 나타낼 수 있습니다.

$$
C(t)=C_0e^{-kt}
$$

여기서 `C0`는 시작 농도, `C(t)`는 시간이 지난 뒤 농도, `k`는 정화속도입니다.

정리하면 k는 다음처럼 구할 수 있습니다.

$$
k=-\frac{\ln(C(t)/C_0)}{t}
$$

| k 해석 | 의미 |
| --- | --- |
| k가 높음 | 오염물질이 빠르게 줄어듦 |
| k가 낮음 | 정화 또는 환기 효과가 약함 |
| k가 음수 | 농도가 줄지 않고 오히려 증가 중 |

앱은 k와 함께 신뢰도를 보조적으로 확인합니다. 값이 너무 흔들리거나 감소 흐름이 뚜렷하지 않으면 정화속도 계산을 그대로 믿기 어렵기 때문입니다.

### 5.3 곰팡이 위험도

곰팡이 위험도는 순간 습도보다 “높은 습도가 얼마나 오래 이어졌는가”를 더 중요하게 봅니다.

| 상태 | 해석 |
| --- | --- |
| 습도 30~60% | 일반적으로 쾌적한 범위 |
| 습도 60~70% | 습도가 높은 편이므로 관찰 필요 |
| 습도 70% 이상 | 고습 상태로 판단 |
| 고습이 장시간 지속 | 곰팡이 위험 단계 상승 |

따라서 잠깐 습도가 오른 것과 하루 종일 습도가 높은 것은 다르게 판단합니다. 이 방식은 욕실, 반지하, 창고처럼 습도가 오래 머무는 공간을 확인하는 데 도움이 됩니다.

## 6. 비교와 히트맵

비교 화면은 실내 센서값과 외부 측정소 값을 함께 보는 화면입니다. 실내 공기질이 나쁠 때 원인이 실내에 있는지, 외부 공기 유입 때문인지 구분하기 위해 만들었습니다.

### 6.1 비교 기준

| 비교 대상 | 의미 |
| --- | --- |
| 등록 센서 | 사용자가 설치한 실내 센서 |
| 공식 측정소 | 환경공단 등 외부 측정소 데이터 |
| 지도 히트맵 | 화면 안의 측정소와 센서값을 색으로 표현 |

실내 PM2.5가 높은데 외부 측정소 값은 낮다면, 조리, 먼지, 실내 활동, 필터 상태 같은 실내 원인을 먼저 의심할 수 있습니다. 반대로 외부 PM2.5도 높다면 환기보다 공기청정이 더 적절할 수 있습니다.

### 6.2 히트맵 항목

| 항목 | 표시 방식 | 비고 |
| --- | --- | --- |
| PM2.5 | 색상 레이어와 측정소 점 | 가장 안정적으로 비교 가능 |
| NOx/NO2 | 측정소 데이터가 있는 곳만 표시 | 데이터가 없는 측정소는 제외 |
| CO | 값이 제공되는 측정소만 표시 | 없으면 표시하지 않음 |
| 온도/습도 | 지도 비교용으로 제한적으로 사용 | 측정소별 제공 여부에 따라 달라짐 |
| CO2/TVOC | 공식 측정소에서 일반적으로 제공하지 않음 | 실내 센서 중심으로 표시 |

데이터가 없는 측정소까지 억지로 표시하면 사용자가 실제 측정값으로 오해할 수 있습니다. 그래서 해당 지표가 없는 측정소는 지도 표시에서 제외하거나 `N/A`로 처리합니다.

### 6.3 색상 해석

히트맵은 값이 낮을수록 초록 계열, 높을수록 노랑·주황·빨강 계열로 보이도록 구성했습니다. 값 자체보다 “어느 지역이 상대적으로 높고 낮은가”를 빠르게 읽는 데 목적이 있습니다.

| 색상 경향 | 해석 |
| --- | --- |
| 초록 | 비교적 안정적인 값 |
| 노랑 | 약간 높거나 관찰이 필요한 값 |
| 주황 | 나쁜 편 |
| 빨강 | 높은 값, 주의 필요 |

지도 위 점은 측정소 또는 등록 센서의 위치를 나타냅니다. 점을 누르면 해당 지점의 이름, 값, 업데이트 시간을 확인할 수 있습니다.

## 7. 알림

알림은 사용자가 계속 앱을 보고 있지 않아도 중요한 변화를 놓치지 않게 하는 기능입니다. Cleanair의 알림은 일반 공기질 알림과 방재 알림을 분리합니다.

### 7.1 일반 공기질 알림

일반 공기질 알림은 항목별로 설정할 수 있습니다.

| 알림 항목 | 예시 |
| --- | --- |
| PM2.5 | 초미세먼지가 나쁨 이상일 때 |
| CO2 | 환기가 필요한 수준일 때 |
| TVOC | 냄새나 화학물질 영향이 커졌을 때 |
| NOx | 연소원이나 외기 유입 영향이 의심될 때 |
| 플러그 | 자동 또는 수동 제어가 발생했을 때 |

사용자가 너무 낮은 단계부터 알림을 받으면 금방 무시하게 됩니다. 그래서 항목별로 알림 민감도를 조절할 수 있게 했습니다.

### 7.2 방재 알림

방재 알림은 일반 공기질 알림보다 더 신중하게 울리도록 구성했습니다.

| 알림 기준 | 의미 |
| --- | --- |
| 경고 이상 | 공기질 이상 흐름이 뚜렷할 때 |
| 강한 경고 이상 | 여러 지표가 함께 나빠지거나 반복될 때 |
| 화재 의심/CO 위험 | 즉시 확인이 필요한 단계 |

“주의” 단계는 흔한 환기 부족이나 조리 냄새에서도 자주 나타날 수 있으므로, 기본적으로 강한 알림 대상에서 제외하는 방향이 더 적절합니다.

### 7.3 백그라운드 알림

앱이 꺼져 있어도 Firebase Cloud Messaging을 통해 알림을 받을 수 있습니다. 사용자는 앱에서 알림 권한과 백그라운드 수신 상태를 확인할 수 있습니다.

## 8. 스마트 플러그

스마트 플러그는 공기질 판단을 실제 대응으로 연결하는 장치입니다. 환기팬, 공기청정기, 경광등, 사이렌, 기타 대응 장치를 플러그에 연결해 사용할 수 있습니다.

### 8.1 제어 방식

| 방식 | 장점 | 사용 상황 |
| --- | --- | --- |
| 로컬 HTTP | 설정이 단순하고 반응이 빠름 | 휴대폰과 플러그가 같은 Wi-Fi에 있을 때 |
| MQTT | 외부 네트워크에서도 제어 가능 | 집 밖에서 플러그를 켜고 끌 때 |

로컬 HTTP는 플러그 IP만 알면 제어할 수 있습니다. MQTT는 플러그 Topic과 MQTT 서버 설정이 필요하지만, 외부에서도 제어할 수 있다는 장점이 있습니다.

### 8.2 수동 제어

수동 제어는 사용자가 직접 ON/OFF를 누르는 방식입니다. 자동 모드가 켜져 있어도 사용자가 직접 조작할 수 있습니다. 다만 수동 모드에서는 자동 제어 로직이 임의로 플러그를 켜거나 끄지 않도록 구분합니다.

### 8.3 자동 제어

자동 제어는 특정 공기질 지표가 기준을 넘으면 플러그를 켜고, 충분히 회복되면 끄는 방식입니다.

기본 구조는 다음과 같습니다.

$$
ON:\ X \geq T_{on}
$$

$$
OFF:\ X \leq T_{off}
$$

여기서 `X`는 선택한 공기질 지표이고, `T_on`은 켜는 기준, `T_off`는 끄는 기준입니다.

ON 기준과 OFF 기준을 분리하는 이유는 히스테리시스 때문입니다. 예를 들어 기준이 1000인데 센서값이 999와 1001을 반복하면 플러그가 계속 켜졌다 꺼질 수 있습니다. 그래서 켜는 기준과 끄는 기준 사이에 여유 구간을 둡니다.

$$
T_{off}<T_{on}
$$

앱에서는 IAQI, CO2, PM2.5, TVOC, NOx 같은 항목을 기준으로 자동 제어 규칙을 설정할 수 있습니다.

### 8.4 제어 기록

플러그 제어는 요청과 응답을 함께 기록합니다.

| 기록 | 의미 |
| --- | --- |
| 요청 | 앱, 서버, 자동제어가 어떤 명령을 보냈는지 |
| 응답 | 플러그가 실제로 ON/OFF 상태를 돌려줬는지 |
| 상태 | 현재 ON/OFF, 온라인 여부 |
| 전력 정보 | 전압, 전류, 전력 |

제어 이력은 앱과 웹 상황판에서 확인할 수 있고 CSV로 저장할 수 있습니다. 시연에서는 “명령을 보냈다”가 아니라 “명령과 응답이 기록으로 남았다”는 점을 보여줄 수 있습니다.

## 9. 방재모드

방재모드는 일반 공기질 악화와 화재 의심 상황을 구분하기 위한 기능입니다. 조리, 먼지, 향, 환기 부족만으로도 PM2.5나 TVOC가 올라갈 수 있기 때문에, 한 항목의 순간값만 보고 바로 위급으로 판단하지 않습니다.

방재모드는 다음 네 가지를 함께 봅니다.

1. 현재값이 높은가
2. 최근 5분 동안 급격히 상승했는가
3. 여러 지표가 동시에 나빠졌는가
4. 같은 흐름이 몇 분 이상 반복되는가

### 9.1 지표별 점수

각 지표는 현재값 점수와 5분 변화량 점수 중 큰 값을 사용합니다.

$$
S(x;C,D)=clamp(\frac{x-C}{D-C},0,2.5)
$$

`C`는 주의 기준, `D`는 위험 기준입니다.

$$
Score_i=\max(S(current_i),S(rise5_i))
$$

| 지표 | 5분 변화 주의/위험 | 현재값 주의/위험 | 단위 |
| --- | --- | --- | --- |
| PM2.5 | 35 / 100 | 75 / 150 | µg/m³ |
| TVOC | 100 / 200 | 200 / 350 | VOC Index |
| 온도 | 3 / 5 | 기준 대비 5 / 8 | °C |
| NOx | 1 / 2 | 2 / 5 | NOx Index |
| CO | 5 / 20 | 10 / 35 | ppm |
| CO2 | 300 / 500 | 1500 / 2500 | ppm |

CO2는 화재 직접 지표라기보다 환기 부족과 재실자 영향을 많이 받습니다. 그래서 방재 점수에는 보조 가중치로만 반영합니다.

### 9.2 위험반응과 동시위험

각 지표의 점수는 다음처럼 해석합니다.

| 점수 | 해석 |
| --- | --- |
| 0.5 미만 | 정상 범위 |
| 0.5 이상 | 주의반응 |
| 1.0 이상 | 위험반응 |

방재모드에서 핵심으로 보는 지표는 PM2.5, TVOC, 온도, NOx입니다. CO 센서가 연결되어 있으면 CO도 핵심 지표에 포함합니다.

동시위험 개수는 핵심 지표 중 위험반응을 보이는 항목 수입니다.

$$
N_{risk}=count(Score_i\geq1.0)
$$

### 9.3 총 위험점수

총 위험점수는 가장 강한 핵심 지표 점수에 동시위험 보너스와 CO2 보조 점수를 더합니다.

$$
R=\max(Score_{core})+0.5(N_{risk}-1)+B_{CO+PM}+w_{CO2}Score_{CO2}
$$

단, 동시위험이 2개 이상일 때만 `0.5(N_risk - 1)`이 붙습니다. CO와 PM2.5가 함께 위험반응이면 `B_CO+PM = 0.25`를 더합니다. CO 센서가 있으면 CO2 가중치는 0.15, CO 센서가 없으면 0.2를 사용합니다.

이렇게 한 이유는 단순히 “TVOC 하나가 높다”는 상황과 “PM2.5, TVOC, 온도, CO가 함께 오른다”는 상황을 다르게 보기 위해서입니다.

### 9.4 화재 의심 후보

CO 센서가 없을 때는 핵심 지표 3개 이상이 함께 위험반응을 보이면 화재 의심 후보가 됩니다.

$$
FireCandidate=N_{risk}\geq3
$$

CO 센서가 있을 때는 다음 조건도 함께 봅니다.

| 조건 | 의미 |
| --- | --- |
| 핵심 위험 3개 이상 | 여러 지표가 함께 나빠짐 |
| CO와 PM2.5 동시 위험 | 연소 또는 불완전 연소 가능성 |
| CO, TVOC, 온도 동시 위험 | 타는 냄새, 열 상승, 가스 상승 조합 |

CO만 단독으로 높게 잡히면 화재 의심이라기보다 CO 위험으로 별도 표시합니다. 이 경우에는 즉시 환기와 연소기기 확인이 우선입니다.

### 9.5 지속성 판단

방재모드는 순간값만으로 최고 단계를 만들지 않습니다. 최근 5분 안에서 화재 의심 후보가 몇 번 반복되었는지 확인합니다.

| 반복 횟수 | 지속성 등급 | 해석 |
| --- | --- | --- |
| 0~1회 | 지속 변화 없음 | 일시적 변화일 가능성 |
| 2~3회 | 확인 필요 | 같은 흐름이 반복됨 |
| 4회 이상 | 반복 감지 | 계속 이어지는 이상 패턴 |

### 9.6 방재 단계

| 단계 | 조건 요약 | 앱 표시와 대응 |
| --- | --- | --- |
| 정상 | 점수와 동시위험이 낮음 | 상태 유지 |
| 주의 | 일부 지표가 가볍게 반응 | 공기질이 조금 나빠졌다는 수준 |
| 경고 | 핵심 지표 1개 이상 위험반응 또는 총점 1 이상 | 환기와 원인 확인 |
| 강한 경고 | 여러 지표가 함께 나빠지거나 반복됨 | 현장 확인, 연결 장치 작동 |
| 화재 의심 | 화재 의심 후보가 반복 감지됨 | 즉시 확인, 필요 시 119 신고 |
| CO 위험 | CO 단독 위험반응 | 즉시 환기, 연소기기 확인 |

이 구조의 목적은 알림을 줄이는 것이 아니라, 정말 중요한 상황에 알림의 무게를 싣는 것입니다. 잦은 조리나 냄새 변화까지 모두 위급으로 처리하면 사용자가 방재 알림을 신뢰하기 어렵습니다.

### 9.7 방재모드에서 할 수 있는 일

- 현재 방재 상태 확인
- 주요 관측값과 5분 변화량 확인
- 센서와 플러그 설치 위치 확인
- 연결 장치 ON/OFF 제어
- 상황 요약 복사와 공유
- 119 전화 화면 열기
- 웹 상황판으로 상황 전송
- 상황 종료 처리

CO 센서값이 들어오는 경우에는 CO 위험 판단도 함께 표시됩니다. 현재 AirGradient ONE 기본 센서 구성에는 CO 센서가 없으므로, CO 값이 없을 때는 해당 항목이 `-` 또는 `N/A`로 표시됩니다.
기판에 CO 센서를 납땜하여 추가하는 것으로, 정확도를 강화할 수 있습니다.

## 10. 웹 상황판

웹 상황판은 앱에서 감지한 상황을 더 큰 화면에서 확인하고, 여러 센서와 플러그를 함께 관리하기 위한 화면입니다. 앱이 1차 사용자용이라면, 웹 상황판은 관리자나 발표 시연자가 상황을 보는 2차 화면에 가깝습니다.

### 10.1 웹 상황판의 역할

| 기능 | 설명 |
| --- | --- |
| 로그인 | 사용자별 센서와 플러그를 분리 |
| 지도 상황판 | 등록된 센서와 플러그 위치 표시 |
| 긴급 배너 | 방재 이벤트가 올라오면 상단에 강조 표시 |
| 상황 상세 | 위치, 시간, 센서값, 판단 근거 확인 |
| 플러그 제어 | 연결 장치를 웹에서도 ON/OFF |
| 상황 종료 | 현장 확인 후 이벤트를 종료 처리 |
| 제어 이력 CSV | 플러그 제어 기록을 파일로 저장 |

### 10.2 앱과 웹의 연결 흐름

```text
앱 방재모드 감지
-> 사용자가 대시보드 전송
-> Firebase에 이벤트 저장
-> 웹 상황판 긴급 배너 표시
-> 지도에서 센서/플러그 위치 확인
-> 필요 시 플러그 제어
-> 현장 확인 후 상황 종료
```

자동으로 119에 신고하는 구조는 넣지 않았습니다. 화재 의심은 매우 민감한 판단이므로, 앱과 웹은 판단에 필요한 정보를 모아주고 최종 신고는 사람이 결정하도록 했습니다.

### 10.3 상황 상세에 들어가는 정보

| 항목 | 이유 |
| --- | --- |
| 위치 | 현장 확인 또는 신고 판단에 필요 |
| 발생 시각 | 일시적 변화인지 지속 상황인지 확인 |
| PM2.5, TVOC, 온도, NOx, CO2, CO | 판단 근거 확인 |
| 위험점수와 동시위험 수 | 왜 단계가 올라갔는지 확인 |
| 연결 플러그 상태 | 대응 장치가 작동 중인지 확인 |
| 최근 이벤트 | 상황이 커지는 중인지 끝난 상태인지 확인 |

### 10.4 사용자에게 주는 의미

웹 상황판은 발표용 장식 화면이 아니라, 앱에서 감지한 상황을 다른 사람이 이어받아 확인할 수 있게 하는 장치입니다. 혼자 쓰는 앱에서는 휴대폰 알림만으로 충분할 수 있지만, 어린이집, 실험실, 사무실, 창고처럼 여러 사람이 함께 관리하는 공간에서는 별도의 상황판이 필요합니다.

Cleanair의 웹 상황판은 그 흐름을 보여주는 제출용 구현입니다. 센서와 플러그 위치를 지도에서 확인하고, 상황을 종료하거나 연결 장치를 제어할 수 있도록 구성했습니다.

## 11. 사용자가 얻는 것

Cleanair가 제공하려는 가치는 세 가지입니다.

첫째, 센서값을 그냥 숫자로 보지 않고 현재 공간이 어떤 상태인지 쉽게 판단할 수 있습니다.
