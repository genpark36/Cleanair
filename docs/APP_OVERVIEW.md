# Cleanair 앱 정보

Cleanair는 실내 공기질을 확인하고, 필요한 경우 환기 장치나 스마트 플러그를 제어하며, 화재가 의심될 수 있는 이상 패턴까지 살펴보는 실내 안전 관리 앱입니다.

사용자가 지금 공간의 상태를 이해하고, 필요한 행동을 바로 선택할 수 있도록 만드는 것이 앱의 목적입니다.

```text
센서 측정
-> Firebase 저장
-> 앱과 웹 상황판에서 실시간 확인
-> 공기질 판단, 건강 모드, 방재모드 표시
-> 알림, 플러그 제어, 상황 전파
```

## 1. Cleanair로 할 수 있는 일

| 기능 | 사용자가 확인할 수 있는 것 |
| --- | --- |
| 메인 대시보드 | 현재 실내 공기질, 주요 오염물질, 방재 상태 |
| 상세 화면 | 시간에 따른 변화, 기준 초과 구간, 구간 통계, CSV 저장 |
| 건강 모드 | 어린이, 고령자, 수면, 집중, 곰팡이, 정화 성능 관점의 해석 |
| 비교 화면 | 실내 센서와 외부 측정소의 차이, 지도 기반 히트맵 |
| 알림 설정 | 항목별 알림 민감도, 방재 알림 기준, Slack 외부 알림 |
| 플러그 | 로컬 또는 MQTT 방식의 스마트 플러그 제어, 자동 제어, 제어 이력 |
| 방재모드 | 화재 의심 패턴, CO 위험, 연결 장치, 상황 요약, 웹 상황판 전송 |
| 웹 상황판 | 여러 센서와 플러그를 지도에서 확인하고 원격 대응 |

## 2. 시스템 구성

Cleanair는 센서, 앱, 서버, 플러그, 웹 상황판이 연동되어 작동합니다.

| 구성 | 역할 |
| --- | --- |
| AirGradient 센서 | 실내의 PM2.5, CO2, TVOC, NOx, 온도, 습도를 측정 |
| Android 앱 | 센서 등록, 위치 저장, 실시간 모니터링, 알림, 플러그 제어 |
| Firebase | 센서 데이터 저장, 알림 처리, 방재 판단, 플러그 명령 처리 |
| Tasmota 플러그 | 공기청정기, 환기팬, 경광등, 사이렌 같은 대응 장치를 ON/OFF |
| 웹 상황판 | 여러 위치의 센서와 플러그를 한 화면에서 확인 |

일반적인 사용 흐름은 다음과 같습니다.

1. 센서에 Cleanair 펌웨어를 설치합니다.
2. 앱에서 센서를 등록합니다.
3. 센서가 설치된 위치를 저장합니다.
4. 필요하면 스마트 플러그를 등록합니다.
5. 앱과 웹 상황판에서 공기질과 방재 상태를 확인합니다.

## 3. 메인 대시보드

메인 대시보드는 앱을 열었을 때 가장 먼저 볼 수 있는 화면입니다. 현재 공간의 전반적인 공기질 상태를 확인할 수 있습니다.
### 3.1 표시 항목

| 항목 | 단위 | 의미 |
| --- | --- | --- |
| IAQI | index | 여러 공기질 지표를 합쳐 보여주는 통합 공기질 지수 |
| PM2.5 | ug/m3 | 초미세먼지 농도 |
| CO2 | ppm | 환기 상태를 판단하는 대표 지표 |
| TVOC | VOC Index | 냄새, 조리, 화학물질 영향이 반영되는 센서 지표 |
| NOx | NOx Index | 연소원, 외기 유입, 조리 영향을 살펴보는 보조 지표 |
| 온도 | degC | 열쾌적성과 방재 판단에 사용 |
| 습도 | % | 쾌적성, 곰팡이 위험도, 건강 모드 판단에 사용 |
| CO | ppm | CO 센서가 연결된 경우 표시되는 일산화탄소 값 |

현재 AirGradient ONE 기본 구성에는 CO 센서가 포함되어 있지 않습니다. Cleanair 펌웨어는 DFRobot SEN0466 CO 센서를 I2C에 연결했을 때 자동으로 감지하고, 값이 유효할 때만 Firebase에 `co` 필드를 추가합니다. CO 센서가 없으면 앱과 서버는 기본형으로 동작하고, CO 값을 0ppm으로 가정하지 않습니다.

### 3.2 통합 공기질 지수

통합 공기질 지수는 CO2, PM2.5, TVOC를 같은 기준으로 바꾼 뒤 가장 나쁜 항목을 중심으로 계산합니다. 단순 평균을 쓰지 않는 이유는 한 항목이 크게 나빠졌을 때 평균치의 함정으로 인해 masking되는 문제를 피하기 위해서입니다.

먼저 각 항목을 기준값과 비교합니다.

$$
r_{CO2}=\max(0,\frac{CO2-600}{400})
$$

$$
r_{PM2.5}=\max(0,\frac{PM2.5-15}{35})
$$

$$
r_{TVOC}=\max(0,\frac{TVOC-100}{100})
$$

각 값은 해당 항목이 기준보다 얼마나 나빠졌는지를 나타냅니다.

| 값 | 의미 |
| --- | --- |
| 0 | 기준보다 낮은 안정적인 상태 |
| 0 초과, 1 미만 | 아직 기준을 초과하지 않았지만 관찰이 필요한 상태 |
| 1 이상 | "나쁨" 기준을 초과한 상태 |

가장 나쁜 항목의 점수를 `m`으로 둡니다.

$$
m=\max(r_{CO2},r_{PM2.5},r_{TVOC})
$$

`m`이 1보다 작으면 지수는 `m`을 그대로 사용합니다. `m`이 1 이상이면 기준 초과 수치만큼 가산합니다.

$$
e=\sum \max(0,r_i-1)
$$

`IAQI_base`는 아래 조건으로 결정합니다.

| 조건 | `IAQI_base` |
| --- | --- |
| `m = 0` | `0` |
| `0 < m < 1` | `m` |
| `m >= 1` | `1 + e` |

지수가 1을 넘는 시점부터 공기질 개선이 필요한 상태로 판단합니다.

### 3.3 열쾌적성 반영

온습도는 직접적인 오염물질은 아니지만, 사용자의 공기질 체감에 큰 영향을 줍니다. Cleanair는 열쾌적성을 반영하여 기준 초과 상황에서 통합 지수에 작은 보정값을 가산합니다.

기준 범위는 다음과 같습니다.

| 항목 | 쾌적 범위 |
| --- | --- |
| 온도 | 20~26 degC |
| 습도 | 30~60% |

온도와 습도 편차는 다음처럼 계산합니다.

$$
D_T=\min(1,\left(\frac{\max(0,20-T,T-26)}{4}\right)^2)
$$

$$
D_H=\min(1,\max((\frac{\max(0,30-RH)}{10})^2,(\frac{\max(0,RH-60)}{20})^2))
$$

$$
D_{thermal}=0.7D_T+0.3D_H
$$

$$
P_{thermal}=0.5D_{thermal}
$$

최종 표시 지수는 다음과 같습니다.

$$
IAQI=\min(6,IAQI_{base}+P_{thermal})
$$

열쾌적성 보정은 온도나 습도 때문에 실제 체감 환경이 나빠지는 경우를 보조적으로 반영합니다.

### 3.4 IAQI 단계

| 단계 | 지수 범위 | 의미 |
| --- | --- | --- |
| 좋음 | 0 | 현재 상태 유지 |
| 보통 | 0 초과, 1 미만 | 큰 문제는 없지만 환기 상태 확인 |
| 조금 나쁨 | 1 이상, 2 미만 | 환기 또는 오염원 확인 필요 |
| 나쁨 | 2 이상, 3 미만 | 환기와 공기청정 강화 권장 |
| 상당히 나쁨 | 3 이상, 4 미만 | 빠른 대응 필요 |
| 매우 나쁨 | 4 이상 | 즉시 대응 필요 |

### 3.5 홈 화면 위젯

Cleanair는 앱을 열지 않아도 현재 상태를 확인할 수 있도록 Android 홈 화면 위젯을 제공합니다.

| 위젯 | 표시 내용 |
| --- | --- |
| 공기질 요약 위젯 | 설치 위치, IAQI, 방재 상태, 온도, 습도, PM2.5, CO2, TVOC, NOx, CO |
| 추세 위젯 | 선택한 측정 항목의 현재값, 상태, 최근 흐름 |

위젯은 앱에서 마지막으로 선택한 센서와 위치 정보를 기준으로 표시합니다. 센서 데이터가 새로 들어오면 앱 내부 상태와 함께 위젯 정보도 갱신됩니다. 위젯을 누르면 Cleanair 앱이 열리며, 홈 화면에서 현재 공기질과 방재 상태를 바로 이어서 확인할 수 있습니다.

CO 센서가 연결되지 않은 기본 구성에서는 CO 값을 표시하지 않거나 `N/A`로 표시합니다. CO 센서가 연결되어 유효한 값이 들어오면 공기질 요약과 방재 판단에 함께 반영됩니다.

## 4. 상세 화면

상세 화면은 현재 값보다 변화 흐름을 보는 곳입니다. 

### 4.1 그래프 범위

| 범위 | 확인하기 좋은 상황 |
| --- | --- |
| 10분 | 조리, 먼지 발생, 급격한 상승 확인 |
| 1시간 | 환기나 공기청정기 작동 후 변화 확인 |
| 6시간 | 하루 중 생활 패턴 확인 |
| 24시간 | 취침 중 CO2 상승, 장시간 환기 부족 확인 |
| 주간 | 반복되는 시간대 확인 |
| 월간 | 장기 경향 확인 |

### 4.2 기준 색상 배경

그래프의 배경 색상은 수치 기준을 의미합니다. X축은 시간이고, Y축 색상은 좋음, 보통, 나쁨 과 같은 오염물 수치, 상태 구간입니다.

예를 들어 PM2.5 그래프에서 선이 초록 영역에 있으면 안정적인 값이고, 노랑이나 주황 영역에 들어가면 기준에 가까워졌거나 기준을 넘은 상태인 것으로 해석할 수 있습니다.

### 4.3 점 선택과 구간 선택

상세 그래프에는 두 가지 확인 방식이 있습니다.

| 모드 | 용도 |
| --- | --- |
| 점 | 특정 시각의 값을 확인 |
| 구간 | 일정 시간 범위의 통계를 확인 |

구간을 선택하면 최댓값, 최솟값, 평균, 중앙값이 표시됩니다.

| 값 | 의미 |
| --- | --- |
| Max | 선택 구간의 최댓값 |
| Min | 선택 구간의 최솟값 |
| Avg | 선택 구간의 평균값 |
| Med | 선택 구간의 중앙값 |

중앙값은 튀는 값이 있을 때 평소 공기질 오염도 수준을 파악할 수 있도록 표시하였습니다.

### 4.4 CSV 저장

CSV 저장은 측정 기록을 파일로 남기는 기능입니다. 저장된 파일은 Android 기준으로 아래 폴더에서 확인할 수 있습니다.

```text
Download/AirGradient
```

최근 30일 전체가 없어도, 30일 안에 실제로 존재하는 데이터는 가능한 만큼 저장합니다.

## 5. 건강 모드

건강 모드는 같은 센서값을 생활 상황에 맞게 다시 해석합니다. 어린이, 고령자, 수면 환경, 집중 환경처럼 상황에 따라 중요한 기준이 다르기 때문입니다.

| 항목 | 주로 보는 값 | 의미 |
| --- | --- | --- |
| 호흡기 건강지수 | PM2.5, CO2, TVOC | 호흡기 부담과 환기 필요성 |
| 고령자 건강지수 | PM2.5, CO2, 온도 | 심혈관과 호흡기 부담 가능성 |
| 집중환경 판단 | CO2, 온도, 습도 | 집중하기 좋은 환경인지 확인 |
| 쾌적 수면지수 | CO2, TVOC, 온습도 | 취침 중 환기와 쾌적성 확인 |
| 곰팡이 위험도 | 습도, 고습 지속 시간 | 장시간 고습에 따른 곰팡이 가능성 |
| 정화속도 k | PM2.5 또는 CO2 변화 | 환기나 공기청정 효과 확인 |
| CADR Index | 정화속도 k 기반 | 공간 내 정화 성능 비교 |

정화속도 k는 오염물질이 얼마나 빠르게 줄어드는지 보는 값입니다.

$$
C(t)=C_0e^{-kt}
$$

$$
k=-\frac{\ln(C(t)/C_0)}{t}
$$

| k 해석 | 의미 |
| --- | --- |
| 높음 | 오염물질이 빠르게 줄어듦 |
| 낮음 | 정화 또는 환기 효과가 약함 |
| 음수 | 농도가 줄지 않고 증가 중 |

## 6. 비교와 히트맵

비교 화면은 실내 센서와 외부 측정소의 수치를 비교하는 기능입니다. 실내 공기질이 나쁠 때 원인이 실내에 있는지, 외부 공기 자체가 나쁜지 판단하는 데 도움이 됩니다.

| 항목 | 표시 방식 |
| --- | --- |
| PM2.5 | 측정소와 등록 센서 값을 색상으로 표시 |
| NOx/NO2 | 데이터가 있는 측정소만 표시 |
| CO | 값이 제공되는 측정소만 표시 |
| 온도/습도 | 제공 가능한 데이터만 제한적으로 표시 |
| CO2/TVOC | 공식 측정소에서 보통 제공하지 않으므로 실내 센서 중심으로 표시 |

데이터가 없는 측정소는 표시하지 않거나 `N/A`로 처리합니다. 실제 값이 없는 지점을 값이 있는 것처럼 보이게 하지 않기 위해서입니다.

히트맵은 화면 안의 측정소와 등록 센서를 바탕으로 색상 레이어를 만듭니다. 초록 계열은 좋음, 노랑과 주황은 각각 약간 나쁨과 나쁨, 빨강은 매우 나쁨을 의미합니다.

## 7. 알림

Cleanair의 알림은 일반 공기질 알림과 방재 알림으로 나뉩니다.

### 7.1 일반 공기질 알림

항목별로 알림을 받을 기준을 설정할 수 있습니다.

| 항목 | 예시 |
| --- | --- |
| PM2.5 | 초미세먼지가 나쁨 이상일 때 |
| CO2 | 환기가 필요한 수준일 때 |
| TVOC | 냄새나 화학물질 영향이 커졌을 때 |
| NOx | 연소원이나 외기 유입 영향이 의심될 때 |
| 플러그 | 자동 또는 수동 제어가 발생했을 때 |

### 7.2 방재 알림

방재 알림은 너무 자주 울리지 않도록 단계별로 받을 수 있도록 설정할 수 있습니다.

| 기준 | 의미 |
| --- | --- |
| 경고 이상 | 공기질 이상 흐름이 뚜렷할 때 |
| 강한 경고 이상 | 여러 지표가 함께 나빠지거나 반복될 때 |
| 화재 의심/CO 위험 | 즉시 확인이 필요한 단계 |

### 7.3 Slack 외부 알림

앱에서 Slack 워크스페이스를 연결하면 경보를 Slack 채널로 보낼 수 있습니다. 연결 뒤에는 앱의 테스트 버튼으로 실제 메시지가 도착하는지 확인할 수 있으며, 실제 긴급 알림을 수신할 수 있습니다.

## 8. 스마트 플러그

스마트 플러그는 공기질 판단을 실제 대응으로 이어주는 장치입니다. 공기청정기, 환기팬, 경광등, 사이렌 같은 장치를 연동할 수 있습니다.

### 8.1 제어 방식

| 방식 | 사용 상황 |
| --- | --- |
| 로컬 HTTP | 휴대폰과 플러그가 같은 Wi-Fi에 있을 때 |
| MQTT | 외부 네트워크에서도 플러그를 제어할 때 |

로컬 HTTP는 플러그 IP를 사용합니다. MQTT는 플러그 Topic과 MQTT 서버 설정을 사용합니다.

새 Tasmota 플러그는 처음 전원을 넣었을 때 자체 Wi-Fi를 엽니다. 그 Wi-Fi에 접속한 뒤 `http://192.168.4.1/`에서 사용할 Wi-Fi를 저장합니다. 이후에는 공유기에서 받은 플러그 IP로 접속하고, 같은 Tasmota 화면에서 MQTT 설정을 입력합니다.

### 8.2 수동 제어

사용자가 직접 ON/OFF를 누르는 방식입니다. 자동 제어가 켜져 있어도 사용자가 직접 조작할 수 있습니다.

### 8.3 자동 제어

자동 제어는 공기질 지표가 기준을 초과하면 플러그를 켜고, 충분히 회복되면 플러그 전원을 차단하는 방식입니다.

$$
ON:\ X \geq T_{on}
$$

$$
OFF:\ X \leq T_{off}
$$

ON 기준과 OFF 기준을 분리하는 이유는 플러그의 히스테리시스 및 오작동 현상을 줄이기 위해서입니다. ex) CO2수치가 1000ppm 근처에서 계속 진동하면 플러그가 불필요한 반복 동작을 지속함

$$
T_{off}<T_{on}
$$

### 8.4 제어 이력

플러그 제어는 요청과 응답을 함께 기록합니다.

| 기록 | 의미 |
| --- | --- |
| 요청 | 앱, 서버, 자동제어가 보낸 명령 |
| 응답 | 플러그가 돌려준 실제 상태 |
| 상태 | 현재 ON/OFF, 온라인 여부 |
| 전력 정보 | 전압, 전류, 전력 |

제어 이력은 앱과 웹 상황판에서 확인할 수 있고 CSV로 저장할 수 있습니다.

## 9. 방재모드

방재모드는 일반적인 공기질 악화와 화재 의심 상황을 구분하기 위한 기능입니다. 조리, 먼지, 향, 환기 부족만으로도 PM2.5나 TVOC가 급증할 수 있으므로, 순간적인 값으로 화재 의심 상황으로 판단하지 않습니다.

방재모드는 다음을 함께 반영합니다.

1. 현재값이 높은가
2. 최근 5분 동안 급격히 상승했는가
3. 여러 지표가 동시에 나빠졌는가
4. 같은 흐름이 반복되는가

### 9.1 지표별 점수

각 지표는 현재값 점수와 5분 변화량 점수 중 큰 값을 사용합니다.

$$
S(x;C,D)=clamp(\frac{x-C}{D-C},0,2.5)
$$

`C`는 주의 기준, `D`는 위험 기준입니다.

$$
Score_i=\max(S(current_i),S(rise5_i))
$$

| 지표 | 5분 변화 주의/위험 | 현재값 주의/위험 | 단위 |
| --- | --- | --- | --- |
| PM2.5 | 35 / 100 | 75 / 150 | ug/m3 |
| TVOC | 100 / 200 | 200 / 350 | VOC Index |
| 온도 | 3 / 5 | 기준 대비 5 / 8 | degC |
| NOx | 1 / 2 | 2 / 5 | NOx Index |
| CO | 5 / 20 | 10 / 35 | ppm |
| CO2 | 300 / 500 | 1500 / 2500 | ppm |

CO2는 환기와 재실자 영향을 많이 받는 측정 지표이므로, 중요도를 낮춰 보조 가중치로 반영합니다.

### 9.2 동시위험

핵심 지표 중 위험반응을 보이는 항목 수를 동시위험으로 상정하였습니다.

$$
N_{risk}=count(Score_i\geq1.0)
$$

핵심 지표는 PM2.5, TVOC, 온도, NOx입니다. CO 센서가 연결되어 있으면 CO도 핵심 지표에 포함합니다.

### 9.3 총 위험점수

$$
R=\max(Score_{core})+0.5(N_{risk}-1)+B_{CO+PM}+w_{CO2}Score_{CO2}
$$

동시위험이 2개 이상일 때만 `0.5(N_risk - 1)`식을 추가로 붙여 산출합니다. CO와 PM2.5가 함께 위험반응을 나타내면 `B_CO+PM = 0.25`항을 더해 계산합니다.

CO 센서가 있으면 CO2 가중치는 0.15, CO 센서가 없으면 0.2를 사용합니다.

### 9.4 방재 단계

| 단계 | 해석 |
| --- | --- |
| 정상 | 화재 의심 패턴이 보이지 않음 |
| 주의 | 일부 지표가 가볍게 반응 |
| 경고 | 공기질 이상 흐름이 뚜렷함 |
| 강한 경고 | 여러 지표가 함께 나빠지거나 반복됨 |
| 화재 의심 | 화재 의심 후보가 반복 감지됨 |
| CO 위험 | CO 값이 위험 수준으로 올라감 |


### 9.5 방재모드에서 할 수 있는 일

- 현재 방재 상태 확인
- 주요 관측값과 5분 변화량 확인
- 센서와 플러그 위치 확인
- 연결 장치 ON/OFF 제어
- 상황 요약 복사와 공유
- 119 전화 화면 열기
- 웹 상황판으로 상황 전송
- 상황 종료 처리

## 10. 웹 상황판

웹 상황판은 앱에서 감지한 상황을 더 큰 화면에서 확인하고, 여러 센서와 플러그를 함께 관리하기 위한 화면입니다.

| 기능 | 설명 |
| --- | --- |
| Google 로그인 | 사용자별 센서와 플러그 구분 |
| 지도 상황판 | 등록된 센서와 플러그 위치 표시 |
| 긴급 배너 | 방재 이벤트 발생 시 상단에 표시 |
| 상황 상세 | 위치, 시간, 센서값, 판단 근거 확인 |
| 플러그 제어 | 웹에서 연결 장치 ON/OFF |
| 상황 종료 | 현장 확인 후 이벤트 종료 |
| 제어 이력 CSV | 플러그 제어 기록 저장 |

앱에서 상황을 웹 상황판으로 전송하면, 웹 상황판에는 긴급 배너와 상세 정보가 표시됩니다. 앱과 웹은 판단에 필요한 정보를 모아주고, 상황에 대한 대처 및 결정은 사람이 하도록 설계했습니다.

## 11. AI 공기질 추천

메인 화면의 AI 공기질 추천은 현재 센서값을 바탕으로 사용자가 바로 할 수 있는 행동을 Google Gemini가 짧게 제안합니다.

예를 들어 CO2가 높으면 환기를 권하고, PM2.5가 높으면 공기청정기 사용을 권합니다. Google Gemini API 호출이 실패하거나 키가 없을 때도 앱이 멈추지 않도록 기본 규칙 기반 추천을 제공합니다.

## 12. Cleanair가 제공하는 가치

Cleanair는 다음 세 가지에 초점을 둡니다.

1. 센서값을 통해 현재 공간의 공기질 상태를 해석합니다.
2. 알림과 플러그 제어 등의 기능으로 현재 상태에 대한 대응을 돕습니다.
3. 화재 의심 상황을 정확히 판별하여 조기에 사용자에게 경고합니다.

평상시에는 공기질 관리 앱으로 쓰고, 이상 상황에서는 조기 감지와 상황 대응을 돕는 방재 도구로 사용할 수 있습니다.
